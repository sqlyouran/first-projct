## Why

当前系统是一个纯信息浏览型的医疗目录应用，用户只能查看医院和专科排名数据。缺少患者之间的互动交流渠道——而患者的真实就医经验往往是其他患者选择医院和科室时最看重的参考。添加交流板块可以提升用户粘性，从"查完就走"变为"查完还想聊"。

## What Changes

- 新增帖子系统：用户可以发布、浏览、查看帖子详情，帖子可选关联多个医院和/或专科（不强制）
- 新增评论系统：帖子下可以发表评论，评论支持一层嵌套回复
- 新增互动功能：帖子和评论支持点赞，帖子支持收藏
- 新增排序机制：帖子列表支持"最新"和"最热"两种排序方式
- 新增 Mock 用户数据：预设若干假用户，为后续用户系统做铺垫（用户注册/登录后置）
- 前端新增"交流"一级导航入口，包含帖子列表页、帖子详情页、发帖页面
- 医院详情页和专科排名页新增关联帖子展示区域
- 内容审核功能延后，不在本次范围内

## Capabilities

### New Capabilities
- `community-posts`: 帖子的发布、列表浏览（最新/最热排序）、详情查看，帖子可选关联医院和专科
- `community-comments`: 帖子评论与一层嵌套回复
- `community-interactions`: 帖子和评论的点赞、帖子的收藏
- `mock-users`: 预设 Mock 用户数据，为社区功能提供作者信息

### Modified Capabilities
- （无现有 spec 变更）

## Impact

- **后端**：新增数据库表（mock_users、posts、comments、post_tags、user_interactions），新增 REST API 端点（帖子 CRUD、评论 CRUD、点赞/收藏接口），新增 Flyway 迁移脚本
- **前端**：新增社区相关页面组件（帖子列表、帖子详情、发帖表单），修改导航布局添加"交流"入口，修改医院详情页和专科排名页添加相关帖子展示
- **API**：新增 `/api/posts`、`/api/posts/{id}/comments`、`/api/posts/{id}/like` 等端点
- **依赖**：无新增外部依赖，复用现有 Spring Boot + JPA + H2 技术栈
